## 할 일

1. 최신 main 기준 npm run verify를 실행하고 저장소/기준 커밋/검증 결과를 기록한다.
2. 브라우저390×844,safe=1에서 첫 실행·이름·브리핑→생활관→전투 투입, 구매/배치/합성/특기 선택·일시정지/계속, 결과→생활관→재투입을 점검한다. 테스트용 저장은 분리하거나 원상복구하고 개인정보·원시 저장값은 보고서에 넣지 않는다.
3. 전체 해금/seed 고정 등 명시한 디버그 조건에서 준비→전투→정산을10웨이브까지 연결해 기계적인 상태 흐름을 검사한다. 갓모드/추가 지급/가속·직접 함수 호출 사용 여부, 계급/특기·시드를 적는다. 단계/데프콘/가스/소생/포격·지원/결과와 예약 정리를 확인한다. 일반 조건의 패배/부활 제안/포기도 별도로 확인한다.
4. 버그가 나오면 재현 조건·기대/실제 동작·영향·사진을 docs/reviews/T-115-integration.md에 기록한다. 제품 수정이 필요하면 해당 경로/변경을 별도 수정 티켓으로 구체화한다. 이 티켓은 점검/안내 문서 범위이며 전투 수치나 제품 코드는 소유하지 않는다.
5. docs/PLAYTEST.md에 로컬 브라우저 실행 방법, 정상 플레이와 전체 해금 체험의 구분, 추천 확인 순서(일반1판→카드/특기 체험), 짧은 기록표를 쓴다. 사용자 기록: 도달 웨이브/걸린 시간/주력 카드·특기/패배 원인/조작 불편/설명 이해/소리 음량/한 판 더 할 의향. 새4종과 A/B가 다른 역할로 느껴지는지도 묻는다.
6. 실제 사용자 결과 없이 재미 게이트/밸런스/사람 플레이 횟수를 충족했다고 쓰지 않는다. 기술 점검 범위와 미확인 사항을 분리하고, 서버/검증 탭 정리·HANDOFF·PR로 인계한다.
