## 판정과 범위

기술적인 준비→전투→정산→10웨이브 승리 흐름을 확인했다. 일반 진입의 첫 실행·생활관·구매/합성/특기·일시정지·포기·패배/부활 제안·재시작도 확인했다. **사람의 재미/난이도/음량 평가와 G1은 미완료**다. 제품 코드는 수정하지 않았다.

- `npm run verify`: 타입 검사, 21파일358테스트, 83에셋 검사, Vite 빌드 통과. 기존 500kB 번들 경고 유지.
- `git diff --check` 통과.
- Chromium, 세로390×844, `safe=1`. 실제 안드로이드 노치/시스템 뒤로가기 검증은 아니다.
- `127.0.0.1:5199`의 별도 BrowserContext에서 저장을 분리했다. 기존 사용자 저장은 읽거나 덮어쓰지 않았다. 검사 후 전용 컨텍스트/탭과 개발 서버를 닫는다.
- 실행 중 발생한 임시 브라우저 연결 실패·잘못된 버튼 선택자는 검사 자동화 오류로 수정했다. 아래 제품 결함과 구분한다.

## 10웨이브 흐름

진입 URL:

```text
http://127.0.0.1:5199/?scene=walk&unlock=all&supply=99&seed=7&safe=1&god=1&deck=rifle:2,blower:1,cook:1,medic:1,signal:1,mortar:1,antitank:1&rank=3&spec=A
```

- 생활관에서 전투 투입. 대기석 카드는 `board.move`로 빈 배치 칸에 이동하고, 저격수·지뢰설치병·화학병 상병A를 `board.place`로 추가했다. 기본 이등병 신병은 유지했다. 총12명/10보직, 추가 구매 없음.
- 2배속. Scene 자동 진행을 잠시 멈추고 실제 `BattleScene.update`를100ms씩 호출했다. 각 준비 단계는 `go()`로 조기 투입했으며 정산은 update로 통과했다. 조기 투입 수입은 게임 기본 동작대로 지급됐다.
- 게임 dt, 사격/표적/소생/가스/포탄/정산/지원/결과 함수는 실제 제품 함수다. 화면 효과 누적을 피하기 위해 캡처용 반복에서는 Phaser UpdateList와 tween dt도100ms씩 진행했다. 난수·렌더링 진행 차이로 전체 처치는 반복별254~256이었다. 승률·밸런스·실시간 프레임 성능의 증거가 아니다.
- 웨이브1~9에서 fight→settle→다음 prep, 웨이브10에서 win을 확인했다. HP20은 `god=1` 결과이므로 난이도 평가에 사용하지 않는다.
- 웨이브7에서 데프콘1로 바뀌고 이전 BGM은 정지, `bgm_defcon1`만 재생 중이었다.
- 가스 출현 기록은7/9/10/10, 네 번이었다. 화학병 제독 기록 합계16칸, 판 끝 남은 가스0칸.
- 지원 버튼으로 요청하고 `pickColumn(2)`로 확정했다. 지원3→2, 실제 `fire_support` 기록과 처치1 확인.
- 별도 중간 확인에서 인접 취사병에 직접 치명 피해를 주고 실제 tickAllies로 의무병 처치를 진행했다. 상병A가 HP101.25/202.5(50%)로 소생, 보호3초, 사용 횟수1 확인. 이 상태 주입도 자연 플레이 성과로 세지 않는다.
- 판 끝 예약 예고/처치선0개, 가스0칸. 결과 후 전투 BGM 둘 다 정지했다. 생활관 복귀 시 WalkScene 활성·생활관 BGM만 재생됐고, 재투입 시 웨이브1/HP20/result=null/부활 미사용으로 초기화됐다. 지원3회는 디버그 덱의 살아 있는 통신병 존재 보너스를 포함한다.
- 반복 검사 중 수집한 window error/unhandled rejection은0건이었다. 이 수집은 디버그 전체 검사에만 적용했다.

사진: [웨이브7](../shots/T-115-wave7.png), [웨이브10 승리](../shots/T-115-win.png). 캡처는 자동 진행으로 만든 상태이며 화면 효과의 체감 평가는 사용자가 해야 한다.

## 발견한 문제와 후속 수정 제안

### 1. 디버그 전투 직행에서 생활관 복귀 불가

- 재현: `?scene=battle&safe=1`로 진입→전투 결과(포기 또는 승패)→‘생활관’.
- 기대: 걷는 생활관이 열리고 재투입할 수 있다.
- 실제: 활성 씬이 빈 배열, 생활관 배경음만 재생되고 상점 잔여 문구/빈 캔버스가 남는다. [재현 사진](../shots/T-115-debug-lobby-bug.png).
- 근거: `src/main.ts`의 battle 직행 scenes 목록에는 WalkScene이 없다. 공통 bindWalk는 `game.scene.start('walk')`를 호출한다.
- 영향: 전투 직행 디버그 동선. 기본 진입/`scene=walk`에서 결과→생활관→재투입은 통과했다.
- 다음 수정 티켓 제안: `src/main.ts`에서 debug battle 진입에도 생활관 씬을 등록하고, `tests/`의 기존 진입/디버그 검사 소유 경로를 명시해 복귀 사례를 추가한다. 현재 티켓에서는 제품 파일을 바꾸지 않았다.

### 2. 자발적 포기에도 ‘위병소 돌파됨’ 표시

- 재현: HP20인 전투에서 일시정지→포기.
- 기대: 사용자가 작전을 포기했음을 결과 제목에 표시한다.
- 실제: 패배 결과 제목은 ‘작전 실패 — 위병소 돌파됨’. [사진](../shots/T-115-quit.png).
- 영향: 결과 원인 오해. 진행/재시작을 막지는 않는다.
- 다음 수정 제안: 별도 티켓에서 `src/battle/BattleScene.ts`→`src/ui/screens.ts` 결과 요청에 포기 원인을 전달하는 범위를 명시하고 포기/실패/성공 문구를 구분한다.
