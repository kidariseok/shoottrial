# 06-02: 해금·기록·이름을 save.ts로, 결과 "생활관" → 로비 (Claude가 직접 쓴 계획, CONTEXT 겸용)

> 우선순위: AGENTS.md > docs/TECH.md §5(저장)·§8(lobby) > 이 계획.
> 브랜치 `kidariseok/m3-core`(main 동기화 완료, T-105 로비 머지됨)에서 바로 한다. 레인 A 파일만 고친다.
> `src/save.ts`(B)는 **import만** 한다.
> - `load(): Promise<Save>`, `save(s): Promise<void>`
> - `Save = { v, name, unlocked: string[], bestWave, runs, firstRun, settings }`
> - 저장소: Capacitor Preferences. 웹은 localStorage `d2_save_v1`

## 확정 결정

- **해금**: `localStorage d2_unlocked` 대신 `save.unlocked`를 쓴다.
  - 처음 한 번 옮긴다. 순수 함수 `mergeUnlocked(saveList, legacyRaw)`(rules.ts)로 `save.unlocked ∪ parseUnlocked(d2_unlocked)`를 만든다.
    - 결과는 `CARD_KEYS` 순서이고 기본 해금을 포함한다.
    - 옮긴 뒤 `d2_unlocked` 키를 지운다(persist.ts `removeKey`, try/catch).
  - 웨이브 5 해금 때 `save.unlocked`를 갱신하고 `save()`한다.
  - `?unlock=all`은 지금처럼 저장하지 않는다.
- **최고 기록·판 수**: 판이 끝날 때(`finish`, 승·패·포기 모두) `bestWave = max(bestWave, wave)`, `runs += 1`을 하고 `save()`한다.
  - 순수 함수 `afterRun(save, wave)` → 새 `{bestWave, runs}`. 테스트로 증명한다.
- **신병 이름**: 신병 카드 이름은 `save.name`이다. 비었으면 `ROOKIE.name`이다.
- **`d2_playlog`(판 기록)**: localStorage에 그대로 둔다(TECH §5: 측정용). persist.ts의 `loadRuns`·`saveRun`도 그대로 둔다.
- **비동기 처리**
  - `create()`에서 `load()`를 기다리는 동안 판을 만들지 않는다. `this.ready` 변수를 두고, `update`는 `ready` 전에는 return한다.
  - `load()`가 끝나면 지금의 판 만들기(보드·신병·덱·상점 첫 채우기)를 실행한다.
  - `load()`가 실패하면 `defaultSave()`(B export)로 진행한다. throw하지 않는다.
  - 저장 쓰기는 기다리지 않는다(`void save(s)`, 실패 무시).
  - 헤드리스가 기다릴 수 있게 `scene.ready`는 public이다.
- **결과 "생활관"**: `onLobby` = `this.scene.stop()` 후 `ui.lobby()`(T-105 구현). 기존 ponytail 주석을 지운다. "다시 출동"은 지금처럼 `restart()`다.
- **`?scene=log`**: 지금처럼 동작해야 한다(save를 기다리지 않아도 됨).
