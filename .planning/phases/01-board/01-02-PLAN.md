`src/battle/board.ts`를 새로 만든다. Phaser 4는 named import를 쓴다(`import { Scene, GameObjects } from 'phaser'`). `../data`에서 LAYOUT·CARDS·CARD_KEYS·UI·SPRITE_SCALE·CardKey를, `../debug`에서 타입 `DeckItem`을 import한다. 클래스·Manager·직접 만든 풀·상태 머신은 쓰지 않는다. 좌표·크기·색·시간 숫자는 모두 data.ts 값을 쓰고 이 파일에 128·720·1280 같은 리터럴을 두지 않는다. 주석은 한국어.

내보낼 것은 위 `<interfaces>`의 계약과 똑같다: 타입 `Unit`, `Zone`, `Slot`, `Board`, 함수 `createBoard(scene, { dy, onSell })`, `deployIndex(col, row)`, `drawRank(gfx, rank)`.

`createBoard`가 하는 일:
1. **구역 도형과 dy 적용**(BOARD-01): **dy는 판 전체에 순효과로 한 번만 적용한다.** `dy`가 코드에 나타나는 곳은 board.ts 안의 세 곳뿐이다 — (가) 판 전체를 담는 컨테이너 `const layer = scene.add.container(0, dy)`, (나) 적 진입 구역 위 끝의 컨테이너 보정 `LAYOUT.hudH - dy`(아래, 월드 위치는 HUD 아래로 고정되므로 이중 이동이 아니다), (다) 카드 뷰용 칸 중심 월드 좌표 계산(아래 2번). BattleScene과 그 밖의 곳은 dy를 더하거나 빼지 않는다. 모든 아래-고정 구역(적 진입·지뢰·배치·방어선·대기석·판매 칸)을 이 `layer` 안의 `GameObjects.Graphics`(및 라벨 텍스트)에 **LAYOUT 좌표 그대로** 그린다 (CONTEXT: "HUD는 위에 고정하고 나머지 판 전체를 dy만큼 아래로", 아래 기준 정렬). HUD 띠(0~hudH)는 `layer` 밖이라 움직이지 않는다. 구역별 색은 UI.colors의 숫자 색, 라벨 텍스트 색은 UI.text의 CSS 문자열(`UI.text.color` 등)을 쓴다.
   - 적 진입 구역: `layer` 로컬 좌표에서 **위쪽을 위로 늘려** 그린다 — 사각형의 위 끝은 로컬 y = `LAYOUT.hudH - dy`(월드로는 HUD 바로 아래), 아래 끝은 `LAYOUT.entryY + LAYOUT.entryRows * LAYOUT.cell`. 폭은 `LAYOUT.width`. 아래 끝에서 위로 `LAYOUT.cell` 간격마다 행 구분선을 위 끝 전까지 그린다. 이렇게 하면 dy를 따로 더하지 않아도 남는 위쪽이 진입로 배경이 되고, dy가 0이면 정확히 entryY~entryY+2행이다.
   - 지뢰 구역: cols x mineRows 격자 칸(테두리). 1단계에서는 놓을 수 없는 곳이다.
   - 배치 구역: cols x deployRows 격자 칸(채움 + 테두리). 칸 (col,row)의 왼쪽 위는 (marginX + col*cell, deployY + row*cell).
   - 방어선: lineY ~ lineY+lineH 띠 + `UI.text.line` 라벨(한국어, UI.text.fontFamily·fontPx·labelColor).
   - 대기석: 띠 배경, 칸 benchSlots개 + 오른쪽 판매 칸 1개. 칸 크기 benchCell, 칸 i의 왼쪽 위 x = benchMarginX + i*benchCell, y = benchY + (benchH - benchCell)/2. 판매 칸은 i = benchSlots이고 UI.colors.sell 색, 라벨 `UI.text.sell`.
2. **칸 목록**: `slots: Slot[]`를 만든다 — deploy 15칸(인덱스 = deployIndex(col,row)), bench 5칸, sell 1칸. Slot.x/y는 **월드 좌표의 칸 중심**이다 — 위 구역 도형에서 쓴 LAYOUT 좌표의 칸 중심에 `dy`를 **여기서 한 번** 더한 값이다(`layer` 컨테이너와 같은 dy이며 이중 적용이 아니다. 카드 뷰는 `layer` 밖 월드에 놓이기 때문). size는 deploy면 LAYOUT.cell, bench·sell이면 LAYOUT.benchCell. plan 03이 히트 판정을 이 목록으로 한다.
3. **카드 도형**: 내부 함수 `makeView(unit, size)`는 `scene.add.container(x, y)`를 만든다. 자식은 컨테이너 중심 기준 좌표로 둔다 — 보직 색 사각형(CARDS[card].color, cell보다 약간 작게 안쪽 여백), 가운데 큰 머리글자(CARDS[card].initial), 오른쪽 위 계급 작대기용 `GameObjects.Graphics`(`drawRank`로 그림), 신병 카드(unit.name이 있을 때)만 아래쪽에 이름 텍스트. 컨테이너는 `setSize(LAYOUT.cell, LAYOUT.cell)`로 크기를 준다. Phaser 컨테이너는 setSize하면 표시 원점이 크기의 절반이 되어 **히트 영역이 컨테이너 중심에 맞춰진다**(자식을 중심 기준 좌표로 두는 것과 일치). 드래그 가능 설정(`setInteractive`)은 plan 03이 하지만 그 히트 영역은 이 size에 맞춰진 **중심 정렬**이어야 한다(plan 03 참조). 배율은 `SPRITE_SCALE * (size / LAYOUT.cell)`(대기석 칸이면 0.875배)로 `setScale`한다(setSize보다 뒤에). 계급 Graphics는 `view.setData('rank', gfx)`로 꺼낼 수 있게 저장한다. 계급 작대기 Graphics는 작대기 묶음의 **중심에 위치(setPosition)** 시켜 그 안에서는 중심 기준으로 그린다(plan 03의 확대 트윈이 제자리에서 커지게).
4. `drawRank(gfx, rank)`: gfx를 clear하고 UI.colors.rankBar 색 가로 막대 `rank`개를 위아래로 쌓아 그린다(rank 1~4, 이등병 1개).
5. `place(zone, i, unit)`: 해당 칸이 비어 있지 않거나 범위 밖이면 false. 비어 있으면 slot.unit/slot.view 채우고 true.
6. `dealDeck(deck)` (DBG-01, per CONTEXT 신병·덱 규칙): `deck`의 각 항목에서 `CARD_KEYS`에 없는 card는 건너뛴다(오타 방지). 항목마다 n장을 만들어(rank 1) **대기석 앞칸(i=0)부터** 빈 칸에 넣고, 대기석이 가득 차면 **배치 구역 빈 칸을 아래 행부터(행 deployRows-1 -> 0, 같은 행은 왼쪽 열부터)** 채우고, 그래도 남으면 버린다. 따라서 `rifle:4,sniper:2`이면 대기석 5칸에 소총수 4 + 저격수 1, 저격수 1장은 배치 구역 맨 아래 행 왼쪽 첫 빈 칸(신병은 가운데 열이므로 왼쪽 열)에 놓인다. `// ponytail: 5칸을 넘는 덱은 배치 구역으로 넘치고 나머지는 버린다, 디버그 전용이라 경고 없음` 주석을 남긴다.

이 task에서는 입력(드래그)을 붙이지 않는다. `onSell`은 아직 부르지 않아도 되지만 시그니처에 받아 둔다(plan 03이 사용). 반환 객체는 `{ place, dealDeck }` 두 개만 가진다.
