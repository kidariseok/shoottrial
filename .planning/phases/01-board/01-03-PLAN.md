**입력(BOARD-02)**: 카드가 칸에 놓이는 모든 경로(`place`, 이동 후 재생성)에서 카드 뷰 컨테이너를 `setInteractive({ draggable: true })`로 만든다. Phaser 이벤트(`scene.input.on('dragstart' | 'drag' | 'dragend', ...)`를 한 번만 등록)를 쓰고 직접 포인터 추적은 만들지 않는다. 이벤트 핸들러에서는 `gameObject.getData('slot')`로 카드 뷰인지 확인한다 — 카드 뷰를 칸에 둘 때마다 `view.setData('slot', slot)`을 갱신한다.

**히트 영역은 카드 중심에 정렬**한다. plan 02에서 `setSize(LAYOUT.cell, LAYOUT.cell)`를 했으므로 컨테이너의 표시 원점은 중심이고, 기본 `setInteractive({ draggable: true })`가 중심 정렬된 영역을 쓴다. 영역을 직접 줄 때는 Phaser 입력이 히트 영역을 객체 **표시 원점(좌상단) 기준 좌표**로 해석하므로 `new Geom.Rectangle(0, 0, LAYOUT.cell, LAYOUT.cell)` + `Geom.Rectangle.Contains`가 중심에 맞는다. 만약 브라우저에서 눌러 봤을 때 영역이 반 칸 어긋나 보이면(중심은 안 눌리고 모서리 쪽만 눌림) `new Geom.Rectangle(-LAYOUT.cell / 2, -LAYOUT.cell / 2, LAYOUT.cell, LAYOUT.cell)`로 바꾼다. 어느 쪽을 쓰든 대기석 0.875배 카드에서도 중심과 네 모서리 근처를 눌러 드래그가 시작되는지 직접 확인한다(아래 human-check).

내부 헬퍼(모두 board.ts 모듈 함수, 클래스 금지):
- `slotAt(x, y)`: slots 중 사각형(중심 x,y, 한 변 size)이 점을 포함하는 칸, 없으면 null. 판 밖·지뢰 구역·방어선 띠는 칸이 아니므로 null.
- `snap(view, x, y)`: `scene.tweens.add({ targets: view, x, y, duration: UI.fx.snapMs })`, 완료 때 depth를 기본값으로 되돌린다. 원위치·이동 모두 이것으로 한다.
- `moveTo(from, to)`: to 칸에 unit·view를 옮기고 from을 비운다. view의 `setData('slot', to)`를 갱신하고 `setScale(SPRITE_SCALE * to.size / LAYOUT.cell)`로 칸 크기에 맞춘 뒤 `snap`으로 to 칸 중심에 보낸다.

동작:
1. **dragstart**: 드래그한 view를 `setDepth(UI.fx.dragDepth)`로 올리고 원래 위치는 출발 Slot의 x,y로 간주한다.
2. **drag**: `gameObject.x = dragX; gameObject.y = dragY`.
3. **dragend**: 놓은 점은 view의 (x, y)이다. `target = slotAt(x, y)`로 분기한다 (결정은 전부 `dropOutcome`):
   - target이 출발 칸 자신이거나 target이 null(판 밖·지뢰 구역): `snap`으로 출발 칸 중심에 원위치. (target=null의 "가까운 빈 칸 보정"은 Task 2가 이 분기를 교체한다.)
   - target.zone이 'sell': `sellFrom(from)` (아래).
   - target이 deploy/bench: `dropOutcome(from.unit, target.unit)`이 'move'면 `moveTo(from, target)`, 'swap'이면 두 칸의 unit·view를 서로 바꿔(`moveTo` 두 번에 해당, 각 view는 새 칸 size로 재조정 + `setData('slot')` 갱신) 두 view가 각자 새 칸 중심으로 스냅, 'merge'면 `mergeInto(from, target)`.
   - 병장끼리는 `merge`가 null이라 `dropOutcome`이 'swap'을 돌려준다 — 별도 처리 없이 이 분기로 자리 바꿈이 된다 (per CONTEXT).

**mergeInto(from, target)** (BOARD-03): 새 계급 = `merge(from.unit, target.unit)` (null이면 원위치로 되돌리고 반환). 이름 상속: `name = target.unit.name ?? from.unit.name` (재료 중 하나라도 신병이면 결과가 이름을 갖는다, BOARD-05 / CONTEXT). 드래그한 view와 대상 칸의 기존 view를 `destroy()`하고 출발 칸을 비운다(unit=null, view=null). 대상 칸에 `{ card, rank: 새 계급, name }`으로 view를 **새로 만든다**(`makeView` 재사용 — 이름 텍스트·계급 작대기가 새 값으로 그려진다; 드래그 설정과 `setData('slot', target)`이 걸리도록 `place`와 같은 내부 함수 `put(slot, unit)`를 공통으로 쓴다). 진급 연출은 Task 2에서 이 함수에 붙인다.

**sellFrom(from)** (BOARD-04): `refund = sellValue(from.unit.card, from.unit.rank)` (이등병 비용 x 재료 장수, 합성 카드는 재료 합 — 신병도 판다). from.view를 `destroy()`, from.unit/view를 null로 비우고 `opts.onSell(refund)`를 부른다(BattleScene이 보급을 더하고 텍스트를 갱신한다 — plan 02에서 연결됨). 확인 창·되돌리기 없음(CONTEXT). 판매 칸은 카드를 담지 않으므로 sell 칸 unit은 항상 null. `// ponytail: 판매 칸이 항상 활성, 2단계에서 phase==='prep'일 때만 허용` 주석.

모든 크기·색·시간은 data.ts 값이다 (이 파일에 숫자·색 리터럴 없음). `// ponytail: 드래그 중 카드 중심 좌표로 칸을 판정한다(손가락 오프셋 없음), 터치 실기기에서 손가락에 가려지면 카드를 손가락 위로 띄운다` 주석을 남긴다. `src/main.ts`·`src/debug.ts`·`src/ui/`·`BattleScene.ts`는 고치지 않는다.

**가까운 빈 칸 보정** (BOARD-02, GDD §8): Task 1의 `dragend`에서 `target === null` 분기(판 밖, 지뢰 구역, 방어선 띠)를 교체한다. 배치 구역 15칸으로 `Cell[]`(칸 중심 x,y와 `free = (unit === null)`)을 만들되 **출발 칸이 배치 구역이면 그 칸도 free=true**로 본다(카드를 들어 올렸으므로). `nearestEmpty(cells, view.x, view.y)`가 인덱스를 주면 `moveTo(from, 그 배치 칸)`, null이면 `snap`으로 원위치(빈 칸 없음). 지뢰 구역은 1단계에서 놓을 수 없는 곳이므로 별도 분기 없이 이 경로를 탄다 (CONTEXT).

**칸 강조** (BOARD-02): 카드 뷰들보다 **아래 depth**의 `GameObjects.Graphics` 하나(`hl`)를 만든다.
- dragstart: 출발 칸을 뺀 모든 칸(deploy·bench·sell)에 대해 `dropOutcome(dragged.unit, 칸.unit)`을 계산해 윤곽선을 그린다 — 'merge'면 `UI.colors.hlMerge`, 그 밖의 놓을 수 있는 칸은 `UI.colors.hlOk` (알파 `UI.fx.hlAlpha`). 지뢰 구역은 칸이 아니므로 강조하지 않는다.
- drag: 매번 `slotAt(view.x, view.y)`로 손 아래 칸을 구하고 **바뀔 때만** `hl`을 다시 그려 그 칸을 `UI.colors.hlHover`로 더 굵게 표시한다.
- dragend: `hl.clear()`.

**반짝임** (BOARD-03): drag에서 손 아래 칸이 'merge' 대상이면 대상 카드의 계급 작대기 Graphics(`target.view.getData('rank')`)에 `scene.tweens.add({ targets: gfx, alpha: ..., duration: UI.fx.flashMs, yoyo: true, repeat: -1 })`를 건다. 다른 칸으로 옮겨가거나 놓을 때 `scene.tweens.killTweensOf(gfx)` 후 `gfx.setAlpha(1)`로 복구한다. `mergeInto`가 대상 view를 destroy하기 **전에** 반드시 해제한다.

**진급 연출** (BOARD-03, GDD §9): `mergeInto`가 새 view를 만든 직후, 새 view의 계급 작대기 Graphics(`getData('rank')`)에 `scene.tweens.add({ targets: gfx, scale: UI.fx.promoteScale, duration: UI.fx.promoteMs, yoyo: true })`를 건다(작대기가 묶음 중심에 위치해 제자리에서 커진다). 그리고 `scene.add.text(target.x, target.y, UI.text.promote, { fontFamily: UI.text.fontFamily, fontSize: UI.text.fontPx + 'px', color: UI.text.popupColor })` — **텍스트 색은 data.ts의 CSS 문자열**(`UI.text.popupColor`)이며 숫자 0x색을 넘기지 않는다 — 를 만들고 트윈으로 y를 `UI.fx.popupRise`만큼 위로, alpha를 0으로 `UI.fx.popupMs` 동안 보낸 뒤 `onComplete`에서 destroy한다 (도형·텍스트만, 피·이미지 없음).
