# 03-TUNING: 경제 튜닝 측정 (TUNE-01)

작성: 03-06 실행(HEAD 2066b09 기준). 현재 결론은 맨 아래 `## 판단`을 본다. 요약: **자동 게이트 두 개 모두 미달이고, 원인은 수치가 아니라 제설병 단독 열 교착(soft-lock)이다. 수치 조정으로는 풀 수 없어 이 계획은 여기서 멈추고 오케스트레이터에게 보고한다(단계를 닫지 않는다).**

## 방법

봇: `.planning/phases/03-econ/tune-bot.mjs` (Node 내장 WebSocket CDP, 새 의존성 없음). 03-CONTEXT "튜닝" 절 규칙 그대로다. 시드마다 격리된 브라우저 컨텍스트(저장소 분리)에서 새 페이지를 열고 `game.scene.pause('battle')` 뒤 **페이지 안에서** 한 번의 `Runtime.evaluate`로 판 전체를 돌린다(걸음 `scene.update(0, 100)` = 0.1초). 캔버스 1개를 단언한다. 시드 4개를 병렬로 돌려도 컨텍스트가 달라 `d2_playlog`·`d2_unlocked`가 섞이지 않는다.

- 준비 단계(`phase === 'prep'`)마다: (1) 살 수 있는 가장 싼 카드부터(동가는 왼쪽 칸) `scene.buy(i)` 반복, 리롤·판매 없음. 보급이 안 줄면(대기석 가득) 멈춘다. (2) 같은 카드·같은 계급(병장 미만) 두 장이 있으면 배치 구역 쪽을 남기고 `board.promote`, 더 못 합칠 때까지. (3) 대기석 카드를 배치 구역 아래 행(row 2)부터 위로, 같은 행은 왼쪽 열부터 빈 칸에 `board.move`, 배치 뒤 다시 합성. 배치로 대기석이 비어 더 살 수 있으면 (1)~(3)을 되풀이한다(이 되풀이는 계획 문장의 해석이다). (4) 지뢰 토큰이 있으면 row 0부터 왼쪽 열 순으로 `board.bury`. (5) `scene.go()` 바로 출동.
- 전투·정산은 걸음만 돌린다. 부활 모달은 두 번째 버튼('포기')으로 거절한다.
- **교착 감지(계획에 없던 추가)**: 한 웨이브 전투가 시뮬레이션 150초(`STALL_SEC`)를 넘으면 `stall`로 끊고 그 웨이브를 도달 웨이브로 적는다(정상 전투는 35초 안쪽). 이유는 `## 판단`.
- 판마다 기록: 시드, 결과, 도달 웨이브(`scene.wave`), `wallSec`, 처치, 마지막 `baseHp`, 걸음, 카드별 구매 수(`runEvents`의 `card_buy`, 참고용), fast/mid/slow.
- 시간 추정: 봇은 항상 바로 출동하므로 `wallSec`이 하한(fast). 준비 시간 상한 합 = `BATTLE.prepFirst + BATTLE.prepNext x (도달 웨이브 - 1)`(30 + 20 x (W-1)초), slow = fast + 합, mid = fast + 0.5 x 합.
- 게이트 기준 상수(스크립트 맨 위): `GATE_GOD_MID_MIN = [6, 10]`분, `GATE_FIRST_WAVE_MIN = 5`.
- 재현(저장소 루트에서, vite가 없으면 스크립트가 5199로 띄우고 끝에 끈다):
  - 초행자 20시드: `node .planning/phases/03-econ/tune-bot.mjs 5199 first`
  - god 5시드: `node .planning/phases/03-econ/tune-bot.mjs 5199 god`
  - 카드 비교: `node .planning/phases/03-econ/tune-bot.mjs 5199 probe`
  - 셋 다: `... 5199 baseline`, 게이트: `... 5199 gate` (종료 코드 0/1)
  - 진단용(게이트 판정에 쓰지 않음): 환경변수 `BOT_SAFE=1`이면 제설병을 같은 열에 소총수·저격수·지뢰설치병이 있을 때만 배치한다.
- 참고: 게임 루프가 pause 직전 한두 프레임을 실시간으로 돌려 같은 시드의 `wallSec`이 +-0.1초 흔들린다(도달 웨이브·결과는 같다).

## 교착 증거와 진단 측정

### 교착 증거 (시드 15, 초행자 봇)

한 웨이브 150초가 지나도 안 끝난 상태를 덤프했다. 배치: 제설병 1(열 0, 배치 칸 10), 소총수 계급 3 1(열 2, 칸 12). 소총수 4장이 계급 3 한 장으로 합쳐져 열 0·2만 채워졌다. 적 보병 1마리(열 0, y 4.02, hp 60 그대로, `knockLeft` 0, `ready` 0)가 제설병 앞에서 밀렸다 걸어왔다를 되풀이한다. 처치 0, 위병소 HP 20. 나머지 5마리는 빈 열의 최후 저지선에 닿아 사라졌다. 제설병은 피해가 0이라 열 0 적은 영원히 안 죽고, 이 열의 소총수가 없어 아무도 못 죽인다. 전투가 끝나려면 적이 0이어야 하므로 판이 끝나지 않는다(사람도 전투 중에는 카드를 못 옮기므로 `포기`가 유일한 탈출).

산술: 제설병 한 번에 밀리는 거리 `ABILITY.knockBase`=1칸, 주기 `CARDS.blower.interval`=1.5초. 같은 시간에 보병이 걷는 거리 0.35 x 1.5 = 0.525칸 < 1칸이라 앞으로 못 나간다. 군견 0.9 x 1.5 = 1.35 < 밀림 1.5(x1.5), 장갑차 0.15 x 1.5 = 0.225 < 0.25(x0.25)도 마찬가지다. 밀리는 동안 걷지도 때리지도 않고(`enemies.ts` 2번), 밀림이 끝나기 전에 준비 시간(`ready`)이 0으로 돌아가 공격도 못 한다.

### 수치로 풀 수 있는가: 시험 1회 (반영 안 함, 되돌림)

"한 노브 +-20%, 한 번에 최대 3개" 안에서 교착을 가장 잘 풀도록 잡은 조합: 제설병 `interval` 1.5 -> 1.8, `ABILITY.knockBase` 1 -> 0.8, 적 4종 `speed` x1.2(보병 0.42, 군견 1.08, RPG병 0.36, 장갑차 0.18). 보병만 봐도 0.42 x 1.8 = 0.756칸 < 0.8칸이라 부등식이 그대로다. 초행자 봇 20시드를 돌린 결과(위 기준선과 같은 방법):

```

wallSec 중앙값 150.2, fast 2.50분, mid 2.75분, slow 3.00분
카드별 구매 합(참고용): rifle52 blower34 sniper12
```
20시드 모두 교착(웨이브 1~3)이었다. 이 값은 `src/data.ts`에 남기지 않았다(되돌림, `git diff HEAD` 비어 있음). 한도 안에서 다른 조합도 같은 부등식이라 풀리지 않는다(제설병 시너지 x1.5, 제설병 두 장이 같은 열에 있으면 밀림이 겹친다).

### 카드 비교 (참고용)

위 기준선의 마지막 표다. 해석: `rifle:5`(기준) 4.5, 저격수 5, 취사병 4, 지뢰설치병 4.5로 거의 비슷하고, **제설병 덱만 1**이다. 제설병 덱 `rifle:3,blower:1`은 합성 뒤 소총수 계급 3 한 장 + 제설병 한 장(+신병)이 되어 위 교착이 그대로 나온 것이다. 시너지·조합 가치와 구매율은 봇이 아니라 G1 사람 확인 사항이다. 이 표는 수치 조정 근거로 쓰지 않았다.

- 이 문제는 게임 규칙의 빈틈이다. 제설병(GDD §5.2: 피해 0, 같은 열 적을 1칸 밀어내 공격 준비 취소)과 "한 열에 제설병만 있는 배치"가 만나면 적 1마리로 웨이브가 영구 정지한다. 처음 하는 사람도 가장 싼 카드를 이어 사다 보면 만난다(초행자 봇 20/20). 그래서 G1 이전에 규칙 결정이 필요하다. 아래 "미해결 / G1 사람 확인"에 선택지를 적었다.
- 참고(판정 아님): 제설병 단독 열을 피하는 진단 봇은 중앙값 5, god mid 9.2~9.5분(교착 안 난 3판)이라 교착만 풀리면 수치는 현재 값에서 크게 벗어나지 않아 보인다. 중앙값이 8을 넘는지는 이 측정에서 해당 없음(초행자 최고는 웨이브 10 승리 1판 mid 8.20분).

## 미해결 / G1 사람 확인

**차단(오케스트레이터 결정 필요, 사람 플레이 항목 아님)**

1. **제설병 단독 열 교착(soft-lock)**. 위 `## 교착 증거와 진단 측정` 참고. 자동 게이트 두 개는 이것 때문에 미달이고 수치 조정(한도 +-20%)으로 풀리지 않는다. 규칙 결정이 필요하다. 후보(결정은 Claude/사용자, 이 계획은 고르지 않았다):
   - (A) 제설병에 아주 작은 피해(예: 소총수의 몇 분의 1)를 줘서 혼자서도 결국 적을 잡게 한다(GDD §5.2 제설병 공격력 0 변경).
   - (B) 같은 적을 연속해서 밀 때마다 밀림 거리가 줄게 한다(밀림 저항), 또는 밀림 뒤 일정 시간은 다시 밀리지 않게 한다.
   - (C) 웨이브 전투 시간 상한: 한 웨이브 전투가 일정 시간을 넘으면 남은 적이 밀리지 않거나 빨라져 교착을 풀게 한다(교착 일반을 막는 안전망).
   - (D) 규칙은 두고 배치 UI(레인 B)가 제설병만 있는 열에 출동 전 경고를 띄운다(수치·규칙 변경은 없지만 전투 중 교착은 그대로다).
   규칙이 바뀌면 `tune-bot.mjs 5199 gate`를 다시 돌려 게이트를 확인한다(스크립트는 그대로 쓸 수 있다). 현재 수치에서 진단 봇은 중앙값 5, god mid 9.2~9.5분이라 수치가 크게 어긋나 보이진 않지만 중앙값 5는 경계값이라 규칙 변경 뒤 재측정이 필요하다.

**G1 시작 전 점검(사람)**

(a) 저장소 비우기. 디버그 판(`?god`·`?wave`·`?supply`·`?deck`·`?speed`)도 기록되므로 브라우저 콘솔에서 먼저 실행한다.

```
localStorage.removeItem('d2_playlog'); localStorage.removeItem('d2_unlocked')
```

(b) 성공 기준 5(사람 확인). `npm run dev`로 개발 서버를 열고 (a)를 한 뒤:
1. `/?scene=battle`(시드 무작위)로 한 판을 끝까지 한다. 스톱워치로 시작~결과 화면 시간을 잰다. 정상 플레이(준비 시간을 보통대로 쓰기)에서 6~10분이면 통과. 이기든 지든 웨이브 5 이상에 닿는지 본다(초행자 기준). **제설병만 놓인 열의 적이 안 죽어 판이 안 끝나는지 눈으로 확인한다(위 교착).**
2. "다시 출동"을 두세 번 해서 다른 보직을 사 보고, 합성이 판 결과를 바꾸는 느낌이 있는지 메모한다(G1 질문 "조합이 결과를 바꿨다").
3. `/?scene=log`를 열어 판 수·평균 판 시간·카드별 구매율이 맞게 보이는지, 구매율 5% 미만(노랑 + "(낮음)")인 카드가 있는지 본다. 한 개라도 있으면 카드 이름과 느낀 이유를 여기 적고 G1 게이트로 넘긴다(구매율 5% 미만 판정은 봇이 아니라 사람 플레이 기록으로 한다). 구매 0 카드는 구매율 0%라 낮음으로 나온다(03-05 메모).
4. 길게 누르기 카드 정보, 일시정지·2배속·포기, 부활 제안(위병소 HP가 0이 되게 해 보기)이 화면에서 자연스러운지 본다.
